\section{Actors and external systems}

The system has four classes of caller and five classes of external dependency.
Every external dependency is optional: the system runs, is tested, and is
demonstrated with all of them absent.

\begin{description}[nosep]
  \item[Library consumer] Imports \texttt{FeedbackInsightAgent} and
    \texttt{Settings} from the package root.
  \item[Operator / analyst] Runs the \texttt{feedback-agent} console script.
  \item[HTTP client] Calls the FastAPI service; the repository ships a
    TypeScript/Vite browser client under \srcfile{frontend/} that consumes
    \texttt{/query}, \texttt{/query/stream}, and \texttt{/chat}.
  \item[CI runner] Executes the same commands as the operator, with the
    deterministic defaults.
\end{description}

\section{Trust boundaries}

Three boundaries matter for the architecture:

\begin{enumerate}
  \item \textbf{Untrusted question text} enters at every entry point and is
    checked by the deterministic input guardrail before retrieval
    (\cref{sec:runtime-stages}).
  \item \textbf{Untrusted retrieved content} --- feedback text is user-authored
    and reaches the prompt --- is checked by a second, separate context
    guardrail, which drops injection-shaped chunks after retrieval and before
    generation. Treating retrieved evidence as untrusted input is the
    structural reason the guardrail is split into two gates rather than one.
  \item \textbf{Credentials} never enter the domain layer. They are read into
    \texttt{Settings} and consumed only by the infrastructure adapters that
    need them.
\end{enumerate}
